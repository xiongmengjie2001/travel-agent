# 产品需求规格（PRD）

> 项目：travel-agent2（旅行规划智能体 Web 应用）
> 版本：v1.0
> 日期：2026-10-03

## 1. 产品概述

用户输入旅行需求（目的地 + 天数 + 预算），AI 自动生成完整行程方案。

## 2. 功能需求（FR）

### FR-1：对话式行程规划

- 用户输入自然语言需求（如"帮我规划北京 3 日游，预算 3000"）
- 系统解析关键参数：目的地、天数、预算、偏好
- 系统生成结构化行程（每日景点、路线、花费、天气）

### FR-2：行程记忆管理

- 保存用户历史行程方案
- 支持按关键词检索历史行程
- 支持删除指定行程

### FR-3：实时天气信息

- 行程中每天显示目的地天气
- 天气数据通过 MCP 工具获取

### FR-4：对话式交互界面

- Web 页面提供类 ChatGPT 的对话输入框
- 行程以卡片形式渲染（目的地 / 天数 / 每日安排 / 总花费）
- 支持连续对话（追问、修改行程）

## 3. 非功能需求（NFR）

### NFR-1：性能

- 单次行程生成响应时间 < 3 秒
- 支持并发 10 个用户

> **响应时间口径**：NFR-1 的 3 秒指后端行程生成接口的处理耗时（请求进入路由 → 返回响应体）；AC-4 的 5 秒指用户提交需求 → 行程卡片渲染完成，含网络往返与前端渲染。二者是同一链路上的不同测量点，非冲突指标。

### NFR-2：可用性

- 前后端分离，API 可独立测试
- DeepSeek API 不可用时降级为模板方案

### NFR-3：安全性

- API Key 不硬编码，从环境变量读取
- 用户输入做注入防护

### NFR-4：可维护性

- 所有模块遵循 SDD 规格文档
- 代码覆盖率 ≥ 80%

## 4. 验收标准（AC）

### AC-1：核心功能

- 输入"北京 3 日游预算 3000" → 返回包含 3 天行程的 JSON
- 行程包含：每日景点列表、路线顺序、预估花费、天气信息

### AC-2：记忆功能

- 生成的行程自动存入 SQLite
- 输入"查看我的历史行程" → 返回已保存的行程列表
- 输入"删除行程 X" → 从数据库移除

### AC-3：接口规范

- 所有 API 返回统一格式：`{"code": 0, "msg": "ok", "data": {...}}`
- 错误返回：`{"code": 非0, "msg": "错误描述", "data": null}`

### AC-4：前端展示

- 浏览器打开 `localhost:5173` 可见对话界面
- 输入需求后 5 秒内看到行程卡片
- 卡片包含：目的地、天数、每日安排、总预算、天气提示

### AC-5：降级可用性

- 断开或置空 DeepSeek API Key 后，输入"北京 3 日游预算 3000"，仍返回结构完整的 3 天行程
- 响应 `data` 中标记 `degraded: true`，前端展示"当前为模板方案"提示
- 降级路径下 AC-1 的结构要求（每日景点列表、路线顺序、预估花费、天气信息）仍然满足
- 降级不触发 5xx；返回 `code` 仍为 0，仅在 `data.degraded` 上区分
